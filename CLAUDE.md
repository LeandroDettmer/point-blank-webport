# CLAUDE.md — point-blank-webport

A browser port of Point Blank (Point Blank Cross client). Client: TypeScript, Vite, three.js, Rapier. Server (`server/`): Node + TypeScript + Postgres; it speaks the original binary protocol. Matches run peer-to-peer (WebRTC). Read `README.md` for setup and `docs/ARCHITECTURE.md` for the overview.

Game assets and the game client are not in this repository. They belong to Zepetto. The code is MIT.

## Layout

| Path | What it is |
|---|---|
| `src/` | client: game, weapons, lobby, HUD, network, P2P host |
| `public/` | static client files. `public/assets/` is generated by `pbx` (git-ignored) |
| `server/src/` | server: Auth and Game TCP, WebSocket web front and `/api`, Postgres |
| `server/runtime/` | server configuration and game data it reads (`Config/`, `Data/`) |
| `server/test/` | server tests and the live smoke script |
| `db/` | `docker-compose.yml` (Postgres 16 only) |
| `db/init/001_init.sql` | schema and game data, loaded on the first start of an empty volume |
| `scripts/` | `dev-all.mjs` (dev supervisor), `pbx.mjs` (runs the exporter), `dev/` smoke scripts |
| `Clients/PBCross/` | your client copy. Git-ignored, never committed |

## Run

```sh
npm install && npm --prefix server install
npm run dev:all          # Postgres (Docker) + server (8090, 39290-39293) + Vite (8000)
npm run dev:all:nowatch  # same, without reload on src/ edits
npm run status           # which process holds each port, and whether it belongs to this repo
```

Open http://localhost:8000. `dev:all` needs Docker running. Its supervisor waits for Postgres (`pg_isready` inside the container) before it starts the server.

## Test

```sh
npm run typecheck                    # client types (tsc --noEmit)
npm --prefix server run typecheck    # server types
npm --prefix server test             # server tests; some need Postgres running
npm run test:net                     # client protocol tests
npm run test:p2p                     # P2P match with real test servers
```

Smoke scripts in `scripts/dev/` and `src/**/dev/` import client code. Some need the generated assets. `npm run build` runs the typecheck first.

## Assets come from pb-extract-tools

`public/assets/` and `src/**/generated` files come from `pb-extract-tools` (sibling folder, or `PB_TOOLS`). Run exports through this repo's wrapper, so the paths are set for you:

```sh
npm run pbx -- doctor
npm run pbx -- export all --client cross --dry-run
npm run pbx -- export all --client cross
npm run pbx -- export titles        # reads server/runtime and db/init/001_init.sql
```

`scripts/pbx.mjs` sets `PB_CLIENTS` (`Clients/`), `PB_ASSETS`, `PB_WEB`, `PB_SERVER` (this repo), `PB_EXTRACTED` and `PB_SNAPSHOTS`. Set them yourself to override. Do not edit the generated files by hand. Change the exporter and run it again.

A full export takes about 20-25 minutes for the Cross client and about 5 GB of `public/assets/`. `.asset-snapshots/` (about 2 GB) is safe to delete.

## Fidelity

- **Values come from the original client.** Take numbers, names, ids and layouts from the client executable, its PEF tables or its packs. Do not guess them.
- **Mark unproven code.** Code that is inferred and not yet confirmed in the client gets a comment `[INFERIDO]`.
- **Mark hand-made code.** Code or data rebuilt by hand, without a source, gets `[RECRIADO]`.
- **No placeholder art.** Do not ship stand-in sprites, models or sounds. Export the real asset, or leave the feature out until it exists.

## Git and secrets

- **Never commit** game files, client copies, `public/assets/`, `extracted/`, `out/`, `.asset-snapshots/`, logs, or database files. They are git-ignored; keep it that way.
- **Never commit secrets.** `server/.env.local`, `.env*` (except `.env.example`), tokens, passwords and TURN credentials stay local. Put new settings in `server/.env.example` with a comment.
- **`server/runtime/Config/` and `server/runtime/Data/` are game data** kept as they are, under the same legal notice as the rest of the game files.

## Adapting to other clients

The port was built and tested against Point Blank Cross. Other Point Blank clients use the same i3Engine formats. To support one, add it in `pb-extract-tools` (`CLIENTS` in `lib/paths.mjs`) and adapt the client code that reads the exported data. AI coding assistants help with this. Point them at this file, `README.md`, the `pbx` commands and the client folder.
